# Проверка комплекта для сдачи

11 ноября 2026 года проект подготовлен как приватный Git-репозиторий [stanislavtvs/modus-feedback](https://github.com/stanislavtvs/modus-feedback). Для передачи жюри владелец должен выдать доступ выбранным участникам; доступ посторонним не открывался.

## Проверенная версия

Проверка исходников выполнена на коммите `3caa994` (предыдущая первая чистая сборка — `9a70314`). Изменение между ними: интерфейс явно показывает выключенное состояние опционального ИИ. После проверки добавлены документация и снимок репетиции; исходники не менялись.

Репозиторий клонирован с GitHub в отдельный каталог. Рабочий `.env` не копировался. Команда `scripts/setup_env.py` создала новые случайные секреты. Docker Compose запущен отдельным проектом `modus-clean-verify` на порту 8029, с собственными томами PostgreSQL и вложений. Рабочая установка на порту 8018 и её данные не использовались для репетиции.

```sh
git clone https://github.com/stanislavtvs/modus-feedback.git
cd modus-feedback
python3 scripts/setup_env.py --port 8029
docker compose -p modus-clean-verify up -d --build --wait
docker compose -p modus-clean-verify exec web python manage.py seed_demo
docker compose -p modus-clean-verify exec web python manage.py test feedback --verbosity 1
docker compose -p modus-clean-verify exec web python manage.py makemigrations --check --dry-run
```

## Результат

- Web и PostgreSQL достигли состояния healthy; миграции и collectstatic выполнились автоматически.
- В новой базе импортированы 20 исходных синтетических обращений.
- Все 31 тест прошли на PostgreSQL, Django system check не обнаружил ошибок.
- `makemigrations --check --dry-run`: No changes detected.
- `.env`, SQLite, кэш Python, файлы загрузок и дампы исключены из Git. Проверка текстовых файлов на фактические значения трёх секретов рабочей установки не обнаружила совпадений.
- Статус Git в проверенной копии чистый: генерация конфигурации и запуск не меняют исходники.
- Базовый запуск не вызывает Ollama: AI_ENABLED=0. VPN для основных функций не нужен. Первая сборка требует интернета для загрузки образов и пакетов.

## Репетиция в браузере

Использована отдельная сессия на 127.0.0.1:8029; сессия рабочей установки localhost:8018 не использовалась.

1. Вход сотрудником `employee`, создание предложения о памятке для новых сотрудников.
2. Назначение Михаилу по категории «Обучение» и срок 7 календарных дней — автоматически.
3. Вход руководителем `manager`; уведомление о новом обращении присутствует.
4. Попытка запроса уточнения без вопроса отклонена с понятной ошибкой.
5. Сохранение вопроса; автор видит статус «Ожидает уточнения» и добавляет комментарий.
6. Руководитель видит уточнение, переводит обращение в работу и затем в «Реализовано» с текстом результата.
7. Автор видит итог, свой комментарий и полную историю четырёх событий. Центр уведомлений содержит три обновления этого обращения.

В тестовой базе создана дополнительная запись MT-0021, поэтому после репетиции там 21 обращение. Это тестовый сценарий, а не утверждение о фактически выполненном улучшении компании. Снимок результата: clean-workflow.jpg.

## Границы проверки

Демо Gemma на реальном сервере было отдельно проверено ранее и описано в VERIFICATION.md. Чистая репетиция проведена с выключенным ИИ, чтобы подтвердить независимость основного процесса от VPN. Корпоративные интеграции Битрикс24/1С, пилот с сотрудниками компании, нагрузочные испытания и полный аудит скринридерами не выполнялись. Приложение не размещалось на публичном домене.

Для реальной интеграции Битрикс24 ещё нужны тестовый портал, разрешённый API-доступ и согласование передаваемых данных. Подготовка репозитория и чистого запуска не означает, что эта интеграция уже реализована.
