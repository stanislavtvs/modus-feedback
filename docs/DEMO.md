# Сценарий представления продукта

Ориентир — 5–7 минут; это рекомендованный сценарий, а не регламент организаторов. Все записи из набора синтетические. Не представляйте их как подтверждённые проблемы компании или реальные показатели эффективности.

## Перед показом

- Запустите Compose по README и выполните seed_demo. Проверьте /health/ и вход под тремя ролями.
- Для работающей Gemma включите AI_ENABLED=1, проверьте доступ к Ollama из Docker и заранее выполните один запрос. Остальной процесс работает без ИИ.
- Откройте employee и manager в разных профилях браузера. Вкладки одного профиля разделяют учётную запись, поэтому не подходят для одновременного показа двух ролей.
- Подготовьте небольшой тестовый TXT/PDF без закрытых данных. Пароль учётных записей — DEMO_PASSWORD из локального .env; не показывайте .env на проекторе.

## Показ

| Этап | Действие | Что объяснить |
|---|---|---|
| Проблема, 30 сек. | Кратко опишите потерю обращений между каналами | Сотруднику нужен видимый результат, руководителю — понятная очередь и ответственный |
| Подача, 60 сек. | employee создаёт предложение, выбирает категорию и прикладывает тестовый материал | Заявка регистрируется, автоматически получает ответственного и срок |
| ИИ и доступность, 60 сек. | В форме покажите помощь Gemma и отдельное применение текста; откройте иконку доступности, крупный текст/контраст | ИИ помогает выразить мысль, решение остаётся за человеком; интерфейс учитывает разные способы взаимодействия |
| Рассмотрение, 90 сек. | manager получает уведомление, запрашивает уточнение; employee отвечает; manager переводит в работу и фиксирует мотивированный итог | Нельзя завершить обращение без текста результата; обсуждение и изменения сохраняются |
| Прозрачность, 45 сек. | employee видит результат и историю; покажите уведомления | Автору не нужно повторно выяснять, что произошло с предложением |
| Управление, 45 сек. | admin открывает /settings/, категории и резервный маршрут; покажите фильтры и аналитику | Если нет ответственного категории, обращение направляется руководителю подразделения или в очередь администраторов |
| Завершение, 30 сек. | Покажите репозиторий и план развития | Работает MVP; интеграции, пилот и промышленное внедрение — следующие этапы |

Пример темы: «Памятка по оформлению заявок для новых сотрудников». Уточнение: для каких заявок и какие поля нужны. Результат в демонстрации явно помечайте как тестовый.

## Что говорить об ограничениях

Уведомления пока только внутри приложения. Поиск похожих тем основан на словах и не доказывает дублирование. Реальных интеграций Битрикс24/1С, SSO, NPS и анонимности нет. Поддержка доступности внедрена, но формальный аудит ещё нужен. Метрики демонстрационного датасета не являются показателями компании.

Если VPN недоступен, продолжите основной процесс без ИИ и честно поясните причину. Можно показать снимок предыдущего реального ответа Gemma, обозначив, что это сохранённый результат, а не текущая генерация.

## Проверка готовности

Репетиция основного цикла на чистой установке выполнена, см. RELEASE_CHECK.md. Живая защита перед жюри, публичное размещение и пилот в компании — отдельные действия и ещё не проводились.
