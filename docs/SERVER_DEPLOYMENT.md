# Развёртывание на сервере университета — 13 ноября 2026

Приложение опубликовано: https://95.57.206.92:8443/. Вход — `/accounts/login/`. ВМ Ubuntu 24.04, отдельный каталог `/home/handyapp/modus-feedback`, Compose-проект `modus-server`. Проверенная версия приложения — c3a750f; последующие изменения этого отчёта относятся к документации.

## Что настроено

- Django/Gunicorn, PostgreSQL 17 и процесс followups работают в отдельных контейнерах с restart: unless-stopped. Docker включён при загрузке ОС.
- Приложение слушает только 127.0.0.1:8018; база не публикуется на интерфейсах хоста.
- В действующий edge nginx добавлен отдельный сервер 8443. Конфигурация сохранена до изменения, nginx -t прошёл, применён reload. В UFW разрешён только дополнительный HTTPS-порт.
- Использован уже действующий публично доверенный сертификат IP-адреса. Его продление обслуживает существующий активный tou-events-renew.timer; nginx уже перезагружается этим механизмом.
- TOU Events и бот продолжают работать, их контейнеры не перезапускались. Основной сайт на 443 отвечает.
- HTTPS=1, DEBUG=0, TRUST_PROXY_HEADERS=1; прокси перезаписывает X-Forwarded-Proto. Имена cookies modus_session/modus_csrf отделены от соседнего сайта на том же IP.
- Разные случайные пароли employee/manager/admin. У фоновых синтетических аккаунтов нет пригодного пароля для входа. Доступы выданы владельцу отдельным файлом, в Git и Docker-образы не входят.
- AI_ENABLED=0 по прямому решению владельца. VPN/Ollama на ВМ не настраивались.

## Данные и проверка

Развёрнута новая база: 20 исходных синтетических обращений. В ходе браузерной проверки создано MT-0021 «Памятка по передаче заявок между отделами», руководитель сохранил учебное решение, автор подтвердил «Помогло». Итого 21 обращение и одна проверка результата. Локальные базы на 8018/8031 на ВМ не копировались.

Все 72 теста прошли непосредственно на сервере в отдельной тестовой PostgreSQL-базе. Для основного тестового набора отключалось HTTP→HTTPS перенаправление и использовались стандартные имена cookies; три отдельных теста проверяют HTTPS-прокси, Secure/CSRF и изоляцию cookies. Реальный вход трёх ролей и сохранение обращения/решения/оценки дополнительно проверены в браузере через публичный HTTPS-адрес.

Django check --deploy: no issues. HTTPS /health/ из текущей сети возвращает 200 и status=ok, сертификат проверяется без обходов. После перезапуска только web/followups сохранились 21 обращение, оценка автора и доступы. Установка не зависит от запущенного компьютера разработчика.

Нагрузочные испытания, формальная проверка безопасности и пилот с сотрудниками компании остаются отдельными этапами. Вложения хранятся на этой ВМ; off-site-копирование не настроено. Для удобного адреса без порта потребуется отдельный домен и DNS-настройка.
