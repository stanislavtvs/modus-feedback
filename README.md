# Модус — обратная связь сотрудников

Работающий MVP для хакатона ГК «Модус Трейд»: сотрудник сообщает о проблеме или предлагает улучшение, система назначает ответственного, руководитель ведёт обсуждение и фиксирует результат. Автор видит весь путь обращения. Интерфейс на русском языке.

## Быстрый запуск из репозитория

Нужны Git, Python 3.10+ (только для генерации настроек), Docker Engine и Docker Compose v2. Для запуска Django на компьютере ничего устанавливать не нужно: зависимости находятся в контейнере.

```sh
git clone https://github.com/stanislavtvs/modus-feedback.git
cd modus-feedback
python3 scripts/setup_env.py
docker compose up -d --build --wait
docker compose exec web python manage.py seed_demo
```

Репозиторий приватный: для клонирования нужен доступ, выданный владельцем. Из ZIP распакуйте проект, перейдите в его каталог и начните с команды `python3 scripts/setup_env.py`.

Откройте http://localhost:8000. Если порт занят, создайте настройки командой `python3 scripts/setup_env.py --port 8029` либо измените `WEB_PORT` в уже существующем `.env`. Скрипт не перезаписывает существующий `.env`. Альтернатива без Python: скопируйте `.env.example` в `.env` и замените три поля секретов случайными значениями (DEMO_PASSWORD — минимум 12 символов).

Скрипт создаёт случайные SECRET_KEY, POSTGRES_PASSWORD и DEMO_PASSWORD. Логины: `employee` — сотрудник закупок, `manager` — руководитель закупок, `admin` — администратор. Пароль всех демо-аккаунтов — значение DEMO_PASSWORD из вашего `.env`. Сам `.env` не входит в репозиторий и архив. Повторный импорт сохраняет записи и существующие пароли, а не сбрасывает их.

Для работы базовых сценариев VPN и Ollama не нужны: ИИ по умолчанию выключен. Первая сборка требует интернета для загрузки образов Docker и Python-пакетов. Чтобы включить реальную Gemma, выполните генерацию `.env` с `--enable-ai` либо установите `AI_ENABLED=1` в существующем файле, настройте OLLAMA_URL/OLLAMA_MODEL и обеспечьте доступ из Docker. После изменения окружения выполните `docker compose up -d`. Работа с обращениями доступна и при выключенном ИИ.

В подготовленной рабочей установке используются порт 8018 и ранее созданный `.env`; не заменяйте их, если хотите сохранить прежние пароли и подключение к VPN.

```sh
docker compose ps
docker compose logs --tail=100 web
docker compose exec web python manage.py test feedback
docker compose exec web python manage.py makemigrations --check --dry-run
docker compose stop
```

Категории, сроки и ответственные настраиваются на собственной странице `/settings/` под `admin`. Техническая админка `/admin/` остаётся для пользователей, профилей и подразделений. Самостоятельной регистрации нет. Для новой учётной записи нужен профиль с подразделением; создать суперпользователя можно через `docker compose exec web python manage.py createsuperuser`.

Демонстрационный сценарий — в [docs/DEMO.md](docs/DEMO.md). Результат проверки чистой установки — в [docs/RELEASE_CHECK.md](docs/RELEASE_CHECK.md).

## Реализовано

- Три типа обращений, категории, подразделения, приоритеты и семь статусов из датасета.
- Создание с описанием, предполагаемым решением и одним вложением; обсуждение и история изменений.
- Назначение по категории → активный руководитель подразделения → очередь администраторов.
- Срок категории в календарных днях, ручное изменение срока, выделение просрочки.
- Обязательная причина для уточнения, отказа, реализации и закрытия. Повторное открытие разрешено руководителю.
- Уведомления внутри приложения о создании, комментариях и изменении обращения.
- Поиск, фильтры по типу, категории, подразделению, статусу, дате, авторству, назначению и просрочке; страницы по 20 записей.
- Аналитика: типы, категории, статусы, доля завершённых, реализованные улучшения, среднее время первого ответа.
- Поиск похожих обращений по совпадению слов, только в доступной пользователю выборке; без обращения к модели (отдельно от помощника Gemma).
- 20 синтетических обращений из предоставленного датасета, импорт с сохранением текста и условных ролей в истории. Для демонстрационных записей добавлены краткие редакционные заголовки; исходные описания сохранены. Даты созданы для демонстрации.
- Инклюзивность: клавиатура, ссылка перехода к содержимому, видимый фокус, семантическая разметка, подписи полей, текстовые ошибки, контрастный режим и крупный текст, адаптация к небольшим экранам, отсутствие обязательной анимации. Настройки сохраняются в браузере.

## Роли и конфиденциальность

Сотрудник видит собственные обращения и назначенные ему. Обрабатывать могут только руководители и администраторы. Руководитель видит своё подразделение и лично назначенные обращения. Администратор видит всё. Комментарии и история имеют те же права, что обращение. Анонимная подача не реализована. Уведомления персональны. Вложения выдаются только после проверки доступа; прямого публичного MEDIA_URL нет.

Один файл до 10 МБ: PDF, PNG, JPEG, UTF-8 TXT. Проверяется расширение и сигнатура, имя на диске случайное; скачивание принудительное. Антивирус и очистка документов не входят в MVP. Не загружайте реальные закрытые данные без разрешения.

## Эксплуатация и ограничения

PostgreSQL хранится в `postgres_data`, вложения — в `uploads`. `docker compose down` сохраняет тома; не используйте `down -v`, если данные нужны. Создавайте резервную копию базы и тома uploads согласованно; восстановление нужно регулярно проверять.

```sh
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup.sql
```

Для промышленного размещения нужны TLS reverse proxy, домен в ALLOWED_HOSTS, CSRF_TRUSTED_ORIGINS, HTTPS=1, проверка безопасности `python manage.py check --deploy`, управление секретами, резервное копирование и мониторинг. Порт по умолчанию опубликован только на 127.0.0.1. Текущий healthcheck рассчитан на локальный HTTP; для HTTPS-развёртывания адаптируйте его к reverse proxy. Демо-аккаунты отключить.

Ограничения MVP: нет email/push, SSO, фоновых напоминаний и эскалаций, интеграций 1С/Битрикс24, опросов/NPS, антивируса, публичного API и формальной сертификации доступности. Совпадение слов не является семантическим анализом. Поиск похожих записей ограничен 500 последними доступными записями, сводка повторов — 100 последними; при росте перейти к PostgreSQL full-text/trigram. История фиксирует изменения из пользовательского процесса; DBA и суперпользователь инфраструктуры остаются доверенными сторонами.

Разработка без Docker допускает `DB_ENGINE=sqlite` только для быстрых локальных тестов; целевое окружение Compose использует PostgreSQL.

## Gemma 4 через Ollama

Подключение выполняет Django через VPN: `OLLAMA_URL=http://10.0.0.7:11434`, `OLLAMA_MODEL=gemma-4-26B-A4B-it-UD-Q8_K_XL:latest`. Эта модель найдена на сервере пользователя. Настройки совпадают с подходом в локальном проекте OpenYou Learn. Адрес не передаётся браузеру, CORS на Ollama не требуется. Доступность VPN должна быть обеспечена именно из Docker.

В создании обращения нажмите «Помочь сформулировать» после ввода описания. Модель предлагает заголовок, описание, категорию, тип и приоритет; применение — отдельной кнопкой. Если форма изменилась после запроса, старый ответ не перезапишет новые правки.

В карточке нажмите «Разобрать обращение»: появятся суть, объяснение простыми словами, вопросы и шаги. Руководителю дополнительно доступен черновик ответа, который можно добавить к полю решения, проверить и сохранить вручную. ИИ не сохраняет статусы, назначения, комментарии и решения самостоятельно.

Передаётся текст текущего обращения (включая предполагаемое решение, текущий результат и последние пять комментариев с ограничением длины), а для черновика — введённый текст и список категорий. Файлы и поля профилей не передаются. Если пользователь сам указал имя в тексте, оно остаётся частью текста. Выборка других обращений модели не передаётся. Запросы требуют входа, POST и CSRF; карточка проверяется на доступ до вызова модели. Ответ проверяется по структуре, длинам и допустимым значениям; отображается как обычный текст.

`AI_ENABLED=0` отключает вызовы, `OLLAMA_TIMEOUT=75` задаёт ожидание (ограничено 90 сек.). Для генерации используется структурированный JSON, think=false, stream=false. В БД хранится только краткоживущая блокировка повторного запроса пользователя, без промптов и ответов. Успешный результат остаётся в странице, пока пользователь его не применит; перезагрузка страницы его сбросит. В случае недоступности модели основной процесс продолжает работать. Миграция 0002 создаётся и применяется стандартным запуском Compose.

Инклюзивные настройки теперь под одной иконкой в шапке: высокий контраст, крупный текст и сброс, закрытие крестиком/Escape/повторным нажатием. Настройки сохраняются локально. Внешний вид остался светло-зелёным.

Технические источники: [Ollama Chat API](https://docs.ollama.com/api/chat), [structured outputs](https://docs.ollama.com/capabilities/structured-outputs).

## Настройки и маршрутизация

Пункт меню ведёт на `/settings/`, в собственный интерфейс приложения. Доступен только системному администратору. Здесь можно создать категорию, изменить её название, активного ответственного и срок от 1 до 365 календарных дней. Пустой ответственный включает маршрут по подразделению автора. Изменение правила не переносит сроки и не переназначает существующие обращения. Для профилей и подразделений пока используется техническая админка по прямому адресу `/admin/`.
