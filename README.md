# Модус — обратная связь сотрудников

Система обратной связи сотрудников ГК «Модус Трейд»: сотрудник сообщает о проблеме или предлагает улучшение, система назначает ответственного, руководитель ведёт обсуждение и фиксирует результат. Автор видит весь путь обращения. Интерфейс на русском языке.

## Быстрый запуск из репозитория

Нужны Git, Python 3.10+ (только для генерации настроек), Docker Engine и Docker Compose v2. Для запуска Django на компьютере ничего устанавливать не нужно: зависимости находятся в контейнере.

```sh
git clone https://github.com/stanislavtvs/modus-feedback.git
cd modus-feedback
python3 scripts/setup_env.py
docker compose up -d --build --wait
docker compose exec web python manage.py seed_demo
```

Репозиторий приватный: для клонирования нужен доступ, выданный владельцем. Из ZIP распакуйте проект, перейдите в его каталог и начните с команды `python3 scripts/setup_env.py`.

Откройте http://localhost:8000. Если порт занят, создайте настройки командой `python3 scripts/setup_env.py --port 8029` либо измените `WEB_PORT` в уже существующем `.env`. Скрипт не перезаписывает существующий `.env`. Альтернатива без Python: скопируйте `.env.example` в `.env` и замените три поля секретов случайными значениями (DEMO_PASSWORD — минимум 12 символов).

Скрипт создаёт случайные SECRET_KEY, POSTGRES_PASSWORD и DEMO_PASSWORD. Логины: `employee` — сотрудник закупок, `manager` — руководитель закупок, `admin` — администратор. Пароль всех демо-аккаунтов — значение DEMO_PASSWORD из вашего `.env`. Сам `.env` не входит в репозиторий и архив. Повторный импорт сохраняет записи и существующие пароли, а не сбрасывает их.

Для работы базовых сценариев VPN и Ollama не нужны: ИИ по умолчанию выключен. Первая сборка требует интернета для загрузки образов Docker и Python-пакетов. Чтобы включить реальную Gemma, выполните генерацию `.env` с `--enable-ai` либо установите `AI_ENABLED=1` в существующем файле, настройте OLLAMA_URL/OLLAMA_MODEL и обеспечьте доступ из Docker. После изменения окружения выполните `docker compose up -d`. Работа с обращениями доступна и при выключенном ИИ.

В подготовленной рабочей установке используются порт 8018 и ранее созданный `.env`; не заменяйте их, если хотите сохранить прежние пароли и подключение к VPN.

```sh
docker compose ps
docker compose logs --tail=100 web
docker compose exec web python manage.py test feedback
docker compose exec web python manage.py makemigrations --check --dry-run
docker compose stop
```

Категории, сроки и ответственные настраиваются на собственной странице `/settings/` под `admin`. Техническая админка `/admin/` остаётся для пользователей, профилей и подразделений. Самостоятельной регистрации нет. Для новой учётной записи нужен профиль с подразделением; создать суперпользователя можно через `docker compose exec web python manage.py createsuperuser`.

Демонстрационный сценарий — в [docs/DEMO.md](docs/DEMO.md). Результат проверки чистой установки — в [docs/RELEASE_CHECK.md](docs/RELEASE_CHECK.md).

## Реализовано

- Три типа обращений, категории, подразделения, приоритеты и семь статусов из датасета.
- Создание с описанием, предполагаемым решением и одним вложением; обсуждение и история изменений.
- Назначение по категории → активный руководитель подразделения → очередь администраторов.
- Срок категории в календарных днях, ручное изменение срока, выделение просрочки.
- Обязательная причина для уточнения, отказа, реализации и закрытия. Повторное открытие разрешено руководителю.
- Уведомления внутри приложения о создании, комментариях и изменении обращения.
- Поиск, фильтры по типу, категории, подразделению, статусу, дате, авторству, назначению и просрочке; страницы по 20 записей.
- Аналитика: типы, категории, статусы, доля завершённых, реализованные улучшения, среднее время первого ответа.
- Поиск похожих обращений по совпадению слов, только в доступной пользователю выборке; без обращения к модели (отдельно от помощника Gemma).
- 20 синтетических обращений из предоставленного датасета, импорт с сохранением текста и условных ролей в истории. Для демонстрационных записей добавлены краткие редакционные заголовки; исходные описания сохранены. Даты созданы для демонстрации.
- Инклюзивность: клавиатура, ссылка перехода к содержимому, видимый фокус, семантическая разметка, подписи полей, текстовые ошибки, контрастный режим и крупный текст, адаптация к небольшим экранам, отсутствие обязательной анимации. Настройки сохраняются в браузере.

## Роли и конфиденциальность

Сотрудник видит собственные обращения и назначенные ему. Обрабатывать могут только руководители и администраторы. Руководитель видит своё подразделение и лично назначенные обращения. Администратор видит всё. Комментарии и история имеют те же права, что обращение. Анонимная подача не реализована. Уведомления персональны. Вложения выдаются только после проверки доступа; прямого публичного MEDIA_URL нет.

Один файл до 10 МБ: PDF, PNG, JPEG, UTF-8 TXT. Проверяется расширение и сигнатура, имя на диске случайное; скачивание принудительное. Антивирус и очистка документов не входят в MVP. Не загружайте реальные закрытые данные без разрешения.

## Эксплуатация и ограничения

PostgreSQL хранится в `postgres_data`, вложения — в `uploads`. `docker compose down` сохраняет тома; не используйте `down -v`, если данные нужны. Создавайте резервную копию базы и тома uploads согласованно; восстановление нужно регулярно проверять.

```sh
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup.sql
```

Для промышленного размещения нужны TLS reverse proxy, домен в ALLOWED_HOSTS, CSRF_TRUSTED_ORIGINS, HTTPS=1, проверка безопасности `python manage.py check --deploy`, управление секретами, резервное копирование и мониторинг. Порт по умолчанию опубликован только на 127.0.0.1. Текущий healthcheck рассчитан на локальный HTTP; для HTTPS-развёртывания адаптируйте его к reverse proxy. Демо-аккаунты отключить.

Ограничения MVP: нет email/push, SSO, интеграций 1С/Битрикс24, опросов/NPS, антивируса, публичного API и формальной сертификации доступности. Совпадение слов не является семантическим анализом. Поиск похожих записей ограничен 500 последними доступными записями, сводка повторов — 100 последними; при росте перейти к PostgreSQL full-text/trigram. История фиксирует изменения из пользовательского процесса; DBA и суперпользователь инфраструктуры остаются доверенными сторонами.

Разработка без Docker допускает `DB_ENGINE=sqlite` только для быстрых локальных тестов; целевое окружение Compose использует PostgreSQL.

## Gemma 4 через Ollama

Подключение выполняет Django через VPN: `OLLAMA_URL=http://10.0.0.7:11434`, `OLLAMA_MODEL=gemma-4-26B-A4B-it-UD-Q8_K_XL:latest`. Эта модель найдена на сервере пользователя. Настройки совпадают с подходом в локальном проекте OpenYou Learn. Адрес не передаётся браузеру, CORS на Ollama не требуется. Доступность VPN должна быть обеспечена именно из Docker.

В создании обращения нажмите «Помочь сформулировать» после ввода описания. Модель предлагает заголовок, описание, категорию, тип и приоритет; применение — отдельной кнопкой. Если форма изменилась после запроса, старый ответ не перезапишет новые правки.

В карточке нажмите «Разобрать обращение»: появятся суть, объяснение простыми словами, вопросы и шаги. Руководителю дополнительно доступен черновик ответа, который можно добавить к полю решения, проверить и сохранить вручную. ИИ не сохраняет статусы, назначения, комментарии и решения самостоятельно.

Передаётся текст текущего обращения (включая предполагаемое решение, текущий результат и последние пять комментариев с ограничением длины), а для черновика — введённый текст и список категорий. Файлы и поля профилей не передаются. Если пользователь сам указал имя в тексте, оно остаётся частью текста. Помощник карточки не получает другие обращения. Отдельный радар использует разрешённую выборку, описанную ниже. Запросы требуют входа, POST и CSRF; карточка проверяется на доступ до вызова модели. Ответ проверяется по структуре, длинам и допустимым значениям; отображается как обычный текст.

`AI_ENABLED=0` отключает вызовы, `OLLAMA_TIMEOUT=75` задаёт ожидание (ограничено 90 сек.). Для генерации используется структурированный JSON, think=false, stream=false. Для помощников черновика и карточки в БД хранится только краткоживущая блокировка повторного запроса пользователя, без промптов и ответов. Успешный результат остаётся в странице, пока пользователь его не применит; перезагрузка страницы его сбросит. В случае недоступности модели основной процесс продолжает работать. Миграция 0002 создаётся и применяется стандартным запуском Compose.

Инклюзивные настройки теперь под одной иконкой в шапке: высокий контраст, крупный текст и сброс, закрытие крестиком/Escape/повторным нажатием. Настройки сохраняются локально. Внешний вид остался светло-зелёным.

Технические источники: [Ollama Chat API](https://docs.ollama.com/api/chat), [structured outputs](https://docs.ollama.com/capabilities/structured-outputs).

## Настройки и маршрутизация

Пункт меню ведёт на `/settings/`, в собственный интерфейс приложения. Доступен только системному администратору. Здесь можно создать категорию, изменить её название, активного ответственного и срок от 1 до 365 календарных дней. Пустой ответственный включает маршрут по подразделению автора. Изменение правила не переносит сроки и не переназначает существующие обращения. Для профилей и подразделений пока используется техническая админка по прямому адресу `/admin/`.

## Четыре дополнительных сценария

- `/radar/` — семантические группы повторяющихся проблем от Gemma. Доступен руководителям и администраторам; анализирует до 24 последних доступных для обработки проблем и предложений. Руководитель редактирует и подтверждает связь или отклоняет группу. Исходные обращения остаются отдельными. Повторный анализ не создаёт ту же группу заново.
- `/followups/` — контроль первого ответа, отсутствия обновлений и просрочки. Отдельный контейнер `followups` проверяет базу каждую минуту; Redis не требуется. По умолчанию: первый ответ 24 ч., отсутствие обновлений 72 ч., эскалация администратору через 24 ч. после напоминания. При уточнении напоминание получает автор. Правила и ручная проверка доступны администратору на этой странице. Все уведомления внутри приложения; повторных уведомлений в рамках одного эпизода нет.
- В карточке реализованного/закрытого обращения автор проверяет решение: «Помогло» или «Проблема осталась». Для второго варианта требуется пояснение; обращение возвращается в работу с новым сроком категории и уведомлением ответственному. Оценка привязана к версии решения. Новое решение требует новой проверки.
- `/improvements/` — модерируемая витрина. После «Помогло» руководитель открывает «Подготовить историю улучшения» в карточке, отдельно редактирует текст «Что было / Что изменилось / Эффект», проверяет аудиторию и публикует. По умолчанию аудитория — подразделение; всю компанию нужно выбрать явно. Черновики не видны. Изменение решения или повторное открытие снимает историю с публикации. Исходное обращение открывается только при наличии прежних прав доступа.

Радар передаёт Ollama идентификаторы, заголовки, ограниченные описания и категории из разрешённой выборки. Поля профилей, файлы и обсуждения в этот анализ не входят; перед передачей пользователь проверяет исходную или замаскированную копию. Имена и нестандартные форматы могут остаться. В базе сохраняются только предложенные группы и их связи, а не полный ответ/промпт. Группы целиком скрываются, если руководитель теряет доступ хотя бы к одному участнику. ИИ не назначает ответственных и не меняет статусы.

Проверка фонового процесса: `docker compose logs --tail=50 followups`. Разовый запуск: `docker compose exec web python manage.py run_followups --once`. Отключить контроль можно в `/followups/`; основной процесс обращений продолжит работать.

## Пульс подразделений и паспорта системных проблем

`/pulse/` показывает количество доступных обращений по подразделениям, незавершённые темы, активные напоминания, обращения, возвращавшиеся автором, и долю подтверждённых актуальных решений. Знаменатель последнего показателя — решения в статусах «Реализовано»/«Закрыто» с версией результата; отклонённые обращения не входят. Старое «Помогло» не засчитывается новой версии. Сотрудник видит сводку своей разрешённой выборки, а не полную статистику подразделения. Рейтингов сотрудников нет.

В подтверждённой группе радара откройте «Создать паспорт системной проблемы». Укажите общую цель, ответственного, план, срок и состояние. Для завершения обязателен результат с описанием проверки. Изменения сохраняются в истории инициативы. Паспорт доступен только руководителям/администраторам с правом обработки всех связанных обращений. Назначение владельца не расширяет права: выбрать можно только активного руководителя/администратора, которому уже доступны все участники группы. Закрытие инициативы не меняет статусы обращений и не ставит оценки за авторов.

## Проверка данных перед ИИ

Все три сценария — черновик, анализ карточки и радар — сначала открывают предварительный просмотр. До подтверждения Ollama не вызывается. Интерфейс показывает адрес получателя, модель, полный пакет пользовательских данных и возможные email, телефоны +7/8, 12-значные идентификаторы и паспортные номера по шаблонам. Скрытие найденных фрагментов включено по умолчанию; исходное обращение не меняется. Можно отменить отправку или явно отправить исходный вариант.

Это эвристическая проверка, а не гарантия удаления персональных данных: имена, адреса и нестандартные форматы могут остаться. Просмотрите весь текст. Сервер подписывает отпечаток пакета на 5 минут, связывает его с пользователем и видом анализа, повторно проверяет доступ и формирует отправляемую копию сам. Изменение данных или истечение срока требует нового просмотра. Промпты и исходные пакеты не сохраняются в истории согласий; подпись содержит только отпечаток, идентификатор пользователя и режим.

## Отдельная демонстрационная установка

```sh
python3 scripts/demo.py up --enable-ai
```

Команда создаёт `.env.demo` с отдельными случайными секретами и запускает Compose-проект `modus-demo` с собственными томами на `http://127.0.0.1:8031/demo/`. Рабочая `.env` и база основного проекта не используются. У веб-приложения демо отдельные имена session/CSRF cookies. Подготовлены 20 исходных синтетических записей, 3 учебных обращения, явно обозначенная вручную подготовленная общая тема, паспорт инициативы и учебная публикация с подтверждением автора. Это заготовки для показа, а не живой ответ ИИ и не измеренный эффект компании.

На каждой странице демо есть заметная маркировка и ссылка на пошаговый маршрут. Используются обычные роли employee, manager, admin; пароль — DEMO_PASSWORD в `.env.demo`. Автоматического входа или обхода прав нет. Основная установка возвращает 404 для `/demo/`, а команда `seed_showcase` отказывается работать без DEMO_MODE=1.

Для автономного показа запустите первый раз без `--enable-ai`. Повторный запуск сохраняет настройки и изменённые записи. Изменять AI_ENABLED или порт существующего демо нужно вручную в `.env.demo`, затем повторить запуск. Остановка с сохранением данных: `python3 scripts/demo.py down`. Скрипт не сбрасывает базу и не удаляет тома. `.env*` исключены из Docker-контекста, секретные окружения — из Git и ZIP.

## План действий и итоговая проверка

В паспорте инициативы есть отдельные шаги: действие, ответственный, срок и отметка выполнения. Шаг можно изменить, вернуть в работу или убрать из плана с возможностью восстановления. Завершение инициативы требует выполнения активных шагов и текста результата. Изменения записываются в историю; статусы связанных обращений автоматически не меняются. При обновлении незавершённые старые планы переносятся построчно в шаги с прежним владельцем и сроком.

Итог совместной проверки — [FINAL_REVIEW.md](docs/FINAL_REVIEW.md). Сценарий выступления и содержание шести слайдов — [PITCH.md](docs/PITCH.md). Это текстовая заготовка; официальный регламент выступления нужно уточнить у организаторов.
